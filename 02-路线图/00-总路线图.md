# AI 辅助读源码与应用实践：统一路线

> 2026-10-27 重构。目标是通过真实应用问题理解实现机制，再用源码解释行为、用实验检验理解。这里的“单元”表示学习顺序，不绑定自然周；一个单元未完成就继续，不为赶进度跳过验证。

## 1. 学习目标

完成后应能做到：

1. **用得出来**：围绕一个小型数据问答场景，运行模型、工具、检索、Agent、湖表写入和查询的最小链路。
2. **追得进去**：从一次真实输入或运行记录定位到固定版本的入口、关键状态变化和输出，亲自核对源码位置。
3. **解释得清**：说明为什么得到这个结果，失败或边界条件怎样处理，以及源码设计对应用的影响。
4. **改得有据**：用同一组输入复跑一个最小改动，比较改动前后的行为与证据。

源码与应用各占一半重心。概念和官方资料用于补足眼前问题，不单独形成一长串待学知识点。只读文档、只跑示例或只让 AI 总结源码，都不能算完成单元。

## 2. 贯穿案例与固定循环

贯穿案例是一个**可追溯的数据问答小助手**：用户问指标口径或某日数据，程序解析问题、查询知识与数据状态、调用只读工具，并在有证据时回答。先复用[第一阶段固定样例](../阶段/阶段一/06-阶段一考点与实践题.md)中的指标、知识文档和分区状态；进入 Paimon/Flink/Spark 时，只增加验证相应机制所需的少量合成行。工作项目中的脱敏问题可替换该案例，但保留相同的验证标准。无需额外搭一套完整业务平台。

每个单元按同一循环执行：

1. **提问与预测**：选一个应用行为或故障，写出输入、预期结果、自己对内部链路的猜测。
2. **运行与记录**：跑最小例子，留下输入、输出、日志/trace、版本和环境。跑不了的部分明确标“未运行”，用官方示例或固定版本代码推演，不能写成已验证。
3. **沿运行链读源码**：从实际入口逐跳核对到关键分支、状态和落点；每个实现结论记 `仓库@commit + 文件:行号`。行号随版本变化，笔记不能只抄本路线图的类名。
4. **改一处再验证**：改变输入、配置或一个受控实现点，覆盖正常路径与一个边界/失败路径；比较预测与实际。
5. **复述并成文**：用一页笔记回答“应用发生了什么、源码为什么这样做、证据在哪里、对下一次设计或排障有什么用”。

每个单元的**最小交付**是一份短记录：运行证据、3–8 个关键源码位置、一张链路图或状态表、一个边界实验、一次应用决策。可复用已有工作成果；缺少哪一项就补哪一项。用[笔记模板](../01-方法论/笔记模板.md)记录，问题进入[问题清单](../03-问题清单/工作问题backlog.md)。

**快进规则**：开始前先尝试直接交出上述证据。已有代码和笔记能覆盖，就标“已掌握”并进入下一单元；不要为了填时间重复练习。建议每次学习留 4–5 小时，但 Flink checkpoint 等复杂机制可以拆成多次。

## 3. 十六个学习单元

| 单元 | 应用问题与最小实验 | 源码追踪重点 | 完成证据 |
| --- | --- | --- | --- |
| 1 · 模型与结构化输出 | 同一问题跑正常、缺字段、歧义输入，比较模型原始消息与程序校验 | LangChain ChatModel 调用、消息与结构化输出的实际路径 | 一条“输入→原始响应→解析→校验”链和失败记录 |
| 2 · 工具与检索 | 给助手加两个只读工具及小知识库；验证非法参数、权限、旧文档和注入文本 | 工具绑定、tool call/ToolMessage、检索和过滤的入口与边界 | 一条完整工具轨迹、一条检索轨迹及反例 |
| 3 · Agent 状态与恢复 | 把助手放进最小 LangGraph；中断、恢复并观察是否重做外部动作 | 状态更新、reducer、checkpoint、interrupt 的实现链 | 状态变化表、恢复实验和副作用结论 |
| 4 · Datus 主链路 | 在固定版本运行一次“提问→SQL/工具→回答”；与自己的助手对照 | 用户入口、上下文构造、工具/SQL 执行、回答落点 | 带源码位置的时序图与一次运行记录 |
| 5 · Datus 上下文与约束 | 同一问题分别给表结构和业务口径；制造非法或无权限请求 | 上下文选择、执行约束、结果校验的实现点 | 答案差异、保护边界和设计取舍 |
| 6 · Datus 故障与改进 | 制造工具失败或 SQL 错误，观察重试/停止；改进自己的助手一处 | 错误传播、重试/停止、可观测性链路 | 改动前后同一用例的运行与源码对照 |
| 7 · Paimon 表与写入 | 把小样例落到追加表/主键表；写入两批并观察版本 | 表语义、写入到提交、snapshot/manifest/data file | 两次写入的逻辑结果和文件/快照关系图 |
| 8 · Paimon 更新与压实 | 更新同一主键，比较最新值、增量变化与物理文件 | merge、compaction、changelog 的关键分支 | 一次更新实验及读写取舍说明 |
| 9 · Paimon 读取与可见性 | 固定 snapshot 重查指标；观察新提交前后的读结果 | scan/split/读取路径和快照选择 | 相同查询在两个版本上的结果及源码解释 |
| 10 · Flink 提交与执行 | 提交最小作业，让记录流经两个算子；定位慢 sink | 图生成、任务部署、算子执行与反压传播 | 提交到执行链路图和一条记录的路径 |
| 11 · Flink 时间与状态 | 输入乱序事件，比较事件时间与处理时间的结果 | keyed state、timer、watermark、迟到数据处理 | 逐事件状态表、预期与实际差异 |
| 12 · Flink checkpoint 与恢复 | 故障前后检查状态和外部副作用，明确重放边界 | barrier、状态快照、ack、完成通知与恢复 | JM/TM 时序图及一次故障推演/运行 |
| 13 · Flink 写 Paimon | 让更新流写入湖表，比较“作业已处理”和“批读可见” | changelog、sink 提交、checkpoint 与 Paimon snapshot 的衔接 | 时间线、可见性实验和失败边界 |
| 14 · Spark 查询计划 | 对同一指标 SQL 查看计划，改变 join/过滤或数据分布 | 解析、优化、物理计划、shuffle/扫描 | 两份计划和一次性能/正确性解释 |
| 15 · Spark 读取 Paimon | 固定口径、截止时间和 snapshot 复算；与 Flink 结果比较 | Paimon 读取适配与版本选择的实现链 | 对账表，逐项归因口径、时点、版本或 SQL |
| 16 · 端到端复盘 | 用用户问题贯穿 Agent→语义定义→Flink→Paimon→Spark | 只补前面证据链中尚未解释的断点 | 一张总图、一条指标合同、一次可复跑对账 |

阶段顺序是 **LangChain/LangGraph（1–3）→ Datus（4–6）→ Paimon（7–9）→ Flink（10–13）→ Spark（14–15）→ 综合（16）**。当工作中出现紧急源码问题，可插队做该单元；回到主线时仍保留固定循环。各仓库的详细问题与入口见[LangChain/LangGraph](00-前置-LangChain-LangGraph巩固路线.md)、[Datus](01-Datus源码阅读路线.md)、[Paimon](02-Paimon源码阅读路线.md)、[Flink](03-Flink源码阅读路线.md)、[Spark](04-Spark源码阅读路线.md)。这些专题文档中的旧周次和大作业是题库，不叠加到本表。

## 4. 横向复盘与支线边界

- **单元 3 后**：同一工具调用在应用代码、LangChain 与 LangGraph 中分别由谁执行、谁保存状态？
- **单元 6 后**：自己的助手与 Datus 在上下文、执行约束和失败恢复上各有什么取舍？
- **单元 9 后**：AI 答案所依据的指标口径与 Paimon 数据版本能否同时固定？
- **单元 13 后**：Flink checkpoint 完成与 Paimon snapshot 可见之间是什么关系？
- **单元 16 后**：给定一个答案，能否一路追到语义定义、SQL、数据时点和源码机制？

业务语义是贯穿案例的约束：至少固定两个指标的粒度、时间、过滤和 SQL 标准答案。可用[数据建模知识框架](../01-方法论/数据建模与语义建模知识框架.md)补缺；[Ossie 实践指南](05-数据建模与Ossie实践指南.md)只在需要表达或交换语义模型时选做，不另开大项目。上下文工程、评估和可靠性在单元 2、3、5、6 中用同一组问题验证，不单独延长为纯概念阶段。

## 5. 开始与验收

**第一次行动**：按[第一周学习单](../阶段/阶段一/07-第一周-模型调用与结构化输出.md)读咕泡 S01/S02，并用[第一阶段题库](../阶段/阶段一/06-阶段一考点与实践题.md)的 A1 正常与歧义样例跑一次；保留原始消息和程序校验结果。随后在[版本锁定](00-版本锁定.md)对应的 LangChain 源码中，从本次调用入口追到响应生成/解析的关键路径，记录 3–5 个亲自核对的位置。最后故意给出非法指标或逆序日期，验证程序拒绝，并写一页笔记。已有项目可完成同样动作，不必重新搭助手。

每阶段完成时，至少能**现场重跑一条应用链、画出带源码位置的主链路、解释一个失败边界**。最终成果是可被别人复核的源码与运行证据，不以读过多少文件或完成多少周计。

版本、源码证据和环境要求见[版本锁定](00-版本锁定.md)与[AI 辅助读源码方法论](../01-方法论/AI辅助读源码方法论.md)。缓存、克隆、实验与调用记录放在 `D:\hy\codex\ai-source-learning` 的任务子目录；最终笔记留在本项目 `04-笔记/`。各阶段材料放在[阶段目录](../阶段/README.md)，按阶段几分子目录。
