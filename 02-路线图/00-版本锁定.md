为什么不锁路线图原文里的 LangChain 1.0：`langchain<=1.0.8` 全线受 CVE-2026-55443（文件路径穿越，涉及 agent 的文件读写与加载器）影响，官方在 1.3.9 修复。1.3.9 仍属 1.x 保守线，且强制要求 LangGraph `>=1.2.4,<1.3`，所以 LangGraph 一起锁到 1.2.16。

## 克隆与切换

```bash
# Flink
git clone https://github.com/apache/flink.git flink
cd flink && git checkout release-1.20.5   # 0980485040c6dbec3a1b32da05c4b655cf01ad2b

# Paimon
git clone https://github.com/apache/paimon.git paimon
cd paimon && git checkout release-1.4.2   # ac223f47d916f4c8e9c07fd1745db448e4e7d0d8

# Spark
git clone https://github.com/apache/spark.git spark
cd spark && git checkout v3.5.9           # 7c14a3c28b141cc97a330c4d0f5d2a6da7267f85

# Datus（读源码用仓库，不用 pip 的包）
git clone https://github.com/Datus-ai/Datus-agent.git datus-agent
cd datus-agent && git checkout v0.4.3     # 2372d43d0e1fe21865fd7b6342a5081786cb0d0f

# LangChain / LangGraph（读运行时源码时用 tag 克隆，日常开发用 pip 锁版）
git clone https://github.com/langchain-ai/langchain.git langchain
cd langchain && git checkout langchain==1.3.9
git clone https://github.com/langchain-ai/langgraph.git langgraph
cd langgraph && git checkout 1.2.16
```

每个仓库按方法论建学习分支：`git checkout -b study/<tag>`。

## Python 环境（阶段 0 / Datus）

```bash
python -m venv .venv && source .venv/bin/activate
pip install "langchain==1.3.9" "langchain-core==1.4.9" "langgraph==1.2.16"
pip freeze > requirements-lock.txt   # 把实际解析结果再固化一层

# Datus
cd datus-agent && pip install -e .
```

依赖约束核对过：`langchain 1.3.9` 要求 `langchain-core>=1.4.6,<2`、`langgraph>=1.2.4,<1.3`，上面三个版本互相兼容。Python 需 3.10+。

## 引擎适配组合（做最小实验时）

Paimon 1.4.2 的仓库里带着现成的引擎模块，正好对上锁定的版本：

- Flink 侧用 `paimon-flink-1.20`（模块路径 `paimon-flink/paimon-flink-1.20`）
- Spark 侧用 `paimon-spark-3.5`（模块路径 `paimon-spark/paimon-spark-3.5`）

注意：`release-1.4.2` 没有 Flink 2.3 的适配模块（最高到 2.2），所以**不要**把 Paimon 1.4.2 和 Flink 2.3 混用。JDK 统一用 17，Maven 3.8+。

## Ossie 专题的版本与环境（2026-10-26 新增）

核心规范标注 `0.2.0.dev0`，是未发布开发草案；相同版本字符串不能唯一标识 Schema，必须同时记录 commit。核心阅读与自建模型使用：

```powershell
# 在 D:\hy\codex\ai-source-learning\ossie-study\upstream 下执行
git clone https://github.com/apache/ossie.git ossie
git -C ossie checkout a498fce5455dcc209605cdbb30b21e47068ff15e
git clone https://github.com/apache/ossie-converters.git ossie-converters
git -C ossie-converters checkout bc4eb5d051dcc1825d90aea7f0c2c4cf89015d3c
git -C ossie-converters submodule update --init --recursive
```

上述转换器提交引用的 `ossie` 子模块是 `7205e15253ae3f340f8f191e978685006f5fa72d`，与核心阅读提交不同。保留转换器配套子模块，按各转换器 README 操作；跨版本交换先比较 Schema，迁移模型副本并记录差异。不要直接替换其子模块为核心阅读版。

核心验证脚本声明 Python >=3.11，依赖声明包含 `jsonschema>=4.26.0`、`pyyaml>=6.0.3`、`sqlglot>=30.12.0`；在专题独立虚拟环境安装并记录实际版本，避免改变阶段 0 / Datus 环境。转换器依赖另按所选目录 README 处理。

本地校验只验证文档与引用等规则；业务数据与指标数值还需独立 SQL 对账。规范、路线图与转换器均按固定提交解读，不把规划中的功能当现成功能。

核对来源：[核心提交](https://github.com/apache/ossie/commit/a498fce5455dcc209605cdbb30b21e47068ff15e)、[转换器提交](https://github.com/apache/ossie-converters/commit/bc4eb5d051dcc1825d90aea7f0c2c4cf89015d3c)、[验证脚本](https://github.com/apache/ossie/blob/a498fce5455dcc209605cdbb30b21e47068ff15e/validation/validate.py)。
