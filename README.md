# AI 辅助读源码

目标：从业务建模出发，形成“指标定义 → 语义模型 → AI 数据问答 → 湖表存储 → 实时计算 → 批查询对账”的完整能力，源码阅读服务于模型设计、结果验证和工作问题。

**统一按 [总学习计划](02-路线图/00-总路线图.md) 执行：22 周，每周约 8 小时。** 顺序是数据建模 → LangChain/LangGraph → Ossie → Datus → Paimon → Flink → Spark；全程复用“订单—支付—退款”案例和一组标准答案。

## 从哪里开始

1. 先读总学习计划的连续周表，确认本周任务与验收。
2. 第 1 周从业务、粒度和指标合同开始，使用 [知识框架](01-方法论/数据建模与语义建模知识框架.md)与 [实践指南](02-路线图/05-数据建模与Ossie实践指南.md)。
3. 每进入一个项目，先查 [版本锁定](02-路线图/00-版本锁定.md)，再打开对应源码指南。
4. 每周把实际产出、验证结果与问题记录到 [笔记进度](04-笔记/README.md)和 [工作问题清单](03-问题清单/工作问题backlog.md)。

## 三条原则

1. 以问题和贯穿案例组织学习，先声明业务口径，再讨论实现。
2. AI 帮助定位、解释和质疑；结论由源码、规范与实验验证。
3. 每周交付可以复述和复核的成果，未运行部分标记“待验证”，完成后再更新进度。
